## 1. Функции как объекты первого класса (First-Class Citizens)

В TypeScript/JavaScript функции — это не просто блоки кода, это **значения**, которые можно:
- Присваивать переменным
- Передавать как аргументы другим функциям
- Возвращать из других функций

### Способы объявления

```typescript
// 1. Function Declaration (всплывает / hoisting)
function add(a: number, b: number): number {
  return a + b;
}

// 2. Function Expression (не всплывает, тип выводится или указывается явно)
const subtract = function(a: number, b: number): number {
  return a - b;
};

// 3. Arrow Function (стрелочная функция, не имеет своего `this`, самый частый выбор)
const multiply = (a: number, b: number): number => {
  return a * b;
};

// 4. Краткая запись стрелочной функции (неявный return)
const divide = (a: number, b: number): number => a / b;
```

**Правило:** Используй `const` со стрелочными функциями по умолчанию. Function Declaration используй только если тебе критически нужен hoisting (что бывает редко в современном коде).

## 2. Область видимости (Scope) и Лексическое окружение

Чтобы понять замыкания, нужно идеально понимать, как TS/JS ищет переменные.

### Виды областей видимости

1. **Global Scope**: Переменные, объявленные вне любых функций/блоков.
2. **Function Scope**: Переменные, объявленные через `var` внутри функции (видны во всей функции).
3. **Block Scope**: Переменные, объявленные через `let` или `const` внутри `{}` (видны только внутри этого блока: `if`, `for`, `while`).

### Лексическое (статическое) связывание

Когда функция выполняется, она ищет переменные не там, **откуда** её вызвали, а там, **где** она была объявлена (в её лексическом окружении).

```typescript
let x = 10; // Глобальная область

function printX() {
  console.log(x); // Ищет x. Не находит локально, идет выше по цепочке -> находит глобальный x =  a = 5;
  console.log(inner()); // 5 (inner "помнит" a из своего лексического окружения)
}

const result = outer();
```

**Почему это важно:** Замыкания — это основной способ создания **приватного состояния** (инкапсуляции) в JavaScript до появления `#private` полей в классах. Они также лежат в основе модульной системы и функциональных паттернов (каррирование, частичное применение).

## 4. Чистые функции (Pure Functions) — КРИТИЧЕСКАЯ КОНЦЕПЦИЯ

Это самая важная тема для твоего пути к формальным методам.

### Определение чистой функции

Функция считается **чистой**, если она удовлетворяет **двум** условиям одновременно:

1. **Детерминированность**: Для одних и тех же аргументов она **всегда** возвращает один и тот же результат.
2. **Отсутствие наблюдаемых побочных эффектов (Side Effects)**: Она не изменяет ничего за пределами своей локальной области видимости.

### Что такое побочный эффект (Side Effect)?

Любое взаимодействие функции с "внешним миром", кроме возврата значения:
- Изменение глобальных переменных или переданных по ссылке объектов/массивов (мутация).
- Ввод/вывод (I/O): `console.log`, `alert`, чтение/запись файлов, сетевые запросы.
- Использование недетерминированных значений: `Math.random()`, `Date.now()`.
- Бросок исключений (`throw new Error()`) — *в строгом ФП это тоже считается эффектом, хотя в TS это допустимо при правильной обработке*.

### Примеры

```typescript
// ❌ НЕЧИСТАЯ (Impure): Мутация аргумента
function appendToArray(arr: number[], item: number): void {
  arr.push(item); // Изменяет исходный массив (побочный эффект)
}

// ✅ ЧИСТАЯ (Pure): Возвращает новый массив, исходный не тронут
function appendToArrayPure(arr: number[], item: number): number[] {
  return [...arr, item];
}

// ❌ НЕЧИСТАЯ: Зависит от внешнего состояния (недетерминированная)
let multiplier = 2;
function multiplyByExternal(x: number): number {
  return x * multiplier; // Если multiplier изменится, результат для того же x будет другим
}

// ✅ ЧИСТАЯ: Все зависимости переданы явно через аргументы
function multiplyPure(x: number, multiplier: number): number {
  return x * multiplier;
}

// ❌ НЕЧИСТАЯ: Побочный эффект I/O
function logAndReturn(x: number): number {
  console.log(x); // I/O эффект
  return x;
}
```

### Почему чистые функции — это святой Грааль?

1. **Легкость тестирования**: Не нужно моковать базу данных, время или глобальные переменные. Просто дал аргументы → проверил результат.
2. **Потокобезопасность (Thread Safety)**: Чистые функции можно безопасно выполнять параллельно, так как они не соревнуются за общее состояние (нет race conditions).
3. **Кэширование (Мемоизация)**: Если функция чистая, мы можем запомнить результат для конкретных аргументов и не вычислять его повторно.
4. **Формальная верификация**: В Hoare Logic (`{P} S {Q}`) гораздо проще доказать корректность чистого преобразования данных, чем отслеживать, как функция изменила 5 разных глобальных переменных.

## 5. Передача по значению vs по ссылке

Чтобы избегать побочных эффектов, нужно понимать, как TypeScript передает данные в функции.

- **Примитивы** (`number`, `string`, `boolean`, `null`, `undefined`): передаются **по значению** (копируются). Изменение их внутри функции не влияет на оригинал.
- **Объекты и массивы**: передаются **по ссылке** (передается ссылка на область памяти). Изменение свойств объекта внутри функции изменит исходный объект.

```typescript
function mutateObject(obj: { value: number }) {
  obj.value = 100; // ⚠️ Побочный эффект: исходный объект изменен!
}

const myObj = { value: 1 };
mutateObject(myObj);
console.log(myObj.value); // 100 (неожиданно для неподготовленного разработчика)
```

**Правило:** Никогда не мутируй аргументы-объекты/массивы внутри функций, если это не является их явной, задокументированной целью (и даже тогда лучше возвращать новую копию).

### Задание 1: Реализация счетчика через замыкание
Напиши функцию `createCounter()`, которая возвращает объект с двумя методами:
- `increment()`: увеличивает счетчик на 1 и возвращает новое значение.
- `getValue()`: возвращает текущее значение счетчика.

**Требование:** Переменная-счетчик должна быть **недоступна** извне напрямую (используй замыкание). Нельзя использовать классы.

### Задание 2: Рефакторинг в чистую функцию
Дана "грязная" функция. Перепиши её так, чтобы она стала **чистой**, не мутировала исходные данные и не зависела от глобальных переменных.

```typescript
let discountRate = 0.1; // Глобальная переменная

function applyDiscount(cart: { total: number, items: string[] }) {
  cart.total = cart.total * (1 - discountRate); // Мутация аргумента
  cart.items.push("free_gift"); // Мутация аргумента
  console.log("Discount applied!"); // Side effect (I/O)
  return cart;
}
```
