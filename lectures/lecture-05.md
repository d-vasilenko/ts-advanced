## Часть 5 из 7: Обработка ошибок (Error handling)

## 🎯 Цель этой части

Научиться предсказуемо и безопасно обрабатывать нештатные ситуации. В твоем калькуляторе это критически важно: пользователь может ввести буквы вместо цифр или попытаться разделить на ноль. Мы научимся обрабатывать это так, чтобы программа не "падала" с нечитаемым стек-трейсом, а корректно сообщала об ошибке.

---

## 1. Объект `Error`

В JavaScript/TypeScript ошибки представляются объектами, наследующими от встроенного класса `Error`.

```typescript
const err = new Error("Деление на ноль невозможно");

console.log(err.name);    // "Error"
console.log(err.message); // "Деление на ноль невозможно"
console.log(err.stack);   // Стек вызовов (где именно произошла ошибка)
```

**Почему это важно:** Свойство `stack` — твой лучший друг при отладке. Оно показывает цепочку вызовов функций, приведшую к ошибке.

---

## 2. Оператор `throw`

Ты можешь "выбросить" (throw) ошибку в любой момент, когда программа сталкивается с некорректным состоянием, которое она не может обработать самостоятельно.

```typescript
function divide(a: number, b: number): number {
  if (b === 0) {
    throw new Error("Делитель не может быть равен нулю");
  }
  return a / b;
}

// divide(10, 0); // Выбросит ошибку и остановит выполнение, если не перехвачена
```

**Правило:** Бросай ошибки **как можно раньше** (Fail Fast). Не позволяй некорректным данным распространяться по программе.

## 3. Конструкция `try...catch...finally`

Чтобы программа не упала при возникновении ошибки, её нужно **перехватить**.

```typescript
try {
  // Код, который может выбросить ошибку
  const result = divide(10, 0);
  console.log("Результат:", result);
} catch (error) {
  // Этот блок выполнится, если в try произошла ошибка
  // error — это объект ошибки (в TS тип unknown, нужно сужать тип!)
  
  if (error instanceof Error) {
    console.error("Произошла ошибка:", error.message);
  } else {
    console.error("Произошла неизвестная ошибка:", error);
  }
} finally {
  // Этот блок выполнится ВСЕГДА, независимо от того, была ошибка или нет
  // Идеально для очистки ресурсов (закрытие файлов, сброс флагов)
  console.log("Операция завершена");
}
```

### Важный нюанс TypeScript: тип `unknown` в `catch`

Начиная с TypeScript 4.0, переменная `error` в блоке `catch` имеет тип `unknown`, а не `any`. Это заставляет тебя проверять тип ошибки перед использованием её свойств (например, `error.message`).

**Правильный паттерн сужения типа (Type Narrowing):**
```typescript
try {
  // ...
} catch (error) {
  if (error instanceof Error) {
    console.log(error.message); // ✅ OK, TS знает, что это Error
  } else {
    console.log("Непредвиденная ошибка:", String(error));
  }
}
```

## 4. Пользовательские классы ошибок

Для сложных систем (Этап 2+) полезно создавать свои классы ошибок, чтобы различать их типы.

```typescript
class DivisionByZeroError extends Error {
  constructor(message: string = "Деление на ноль") {
    super(message);
    this.name = "DivisionByZeroError";
    // Необходимо для корректной работы instanceof в TypeScript при наследовании от Error
    Object.setPrototypeOf(this, DivisionByZeroError.prototype);
  }
}

// Использование:
try {
  throw new DivisionByZeroError();
} catch (error) {
  if (error instanceof DivisionByZeroError) {
    console.log("Специфичная обработка деления на ноль");
  } else if (error instanceof Error) {
    console.log("Общая ошибка:", error.message);
  }
}
```
*Для Модуля 0.1 обычного `new Error()` вполне достаточно, но знать о существовании кастомных ошибок полезно.*

## 5. Ошибки vs Возврат специальных значений (Result Type)

В Части 3 ты писал функцию `safeDivide`, которая возвращала `number | "error"`. Это допустимый паттерн, но у него есть минусы:
-caller функции обязан каждый раз проверять, не вернулась ли строка `"error"`.
- Это не масштабируется (что если нужно вернуть код ошибки и сообщение?).

В современном TypeScript и ФП для этого используют паттерн **Result** (или `Either`), но для нашего текущего калькулятора классический `try/catch` с `throw new Error()` будет более идиоматичным и чистым решением для обработки фатальных ошибок ввода.
