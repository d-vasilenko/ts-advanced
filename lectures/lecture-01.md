## 1. Что такое тип данных?

**Тип данных** — это классификация данных, которая определяет:
- Какие значения может принимать переменная
- Какие операции над ней допустимы
- Как она хранится в памяти

В TypeScript есть **примитивные типы** (атомарные, неделимые) и **составные типы** (объекты, массивы, функции).

### Примитивные типы TypeScript

```typescript
// Числа (все числа — это number, включая целые и дробные)
let age: number = 25;
let price: number = 19.99;
let negative: number = -10;
let infinity: number = Infinity;    // Специальное значение
let notANumber: number = NaN;       // Not a Number (тоже number!)

// Строки
let name: string = "Денис";
let greeting: string = 'Привет';    // Одинарные кавычки тоже работают
let template: string = `Меня зовут ${name}`;  // Template literal

// Булевые (true/false)
let isActive: boolean = true;
let hasError: boolean = false;

// null и undefined (отсутствие значения)
let empty: null = null;             // Явное "ничего"
let notAssigned: undefined = undefined;  // Не присвоено

// void (отсутствие возвращаемого значения)
function logMessage(): void {
  console.log("Hello");
}

// bigint (для очень больших целых чисел)
let hugeNumber: bigint = 9007199254740991n;  // Обратите внимание на 'n'

// symbol (уникальные идентификаторы, редко нужны)
let uniqueId: symbol = Symbol("id");
```

### Почему это важно для тебя

TypeScript — это **статически типизированный язык**. Это значит, что типы проверяются **во время компиляции**, а не во время выполнения программы. Это даёт:

1. **Раннее обнаружение ошибок**: если ты попытаешься сложить строку и число, TS покажет ошибку ДО запуска программы
2. **Самодокументирующийся код**: по сигнатуре функции понятно, что она принимает и возвращает
3. **Рефакторинг**: IDE подсказывает, где нужно изменить код, если ты изменил тип
4. **Основа для теории типов**: то, что ты учишь сейчас — это простейшая форма системы типов. В Lean 4 ты будешь работать с гораздо более мощной системой, но принципы те же.

## 2. Type Annotation vs Type Inference

### Type Annotation (явное указание типа)

Ты сам говоришь TypeScript, какой тип у переменной:

```typescript
let age: number = 25;
let name: string = "Денис";
let isActive: boolean = true;
```

**Когда использовать:**
- Когда тип неочевиден из значения
- Когда ты хочешь явно задокументировать намерение
- Когда тип — это union или сложный тип

### Type Inference (автоматический вывод типа)

TypeScript сам понимает тип из значения:

```typescript
let age = 25;           // TS понимает: number
let name = "Денис";     // TS понимает: string
let isActive = true;    // TS понимает: boolean
```

**Когда использовать:**
- Почти всегда. Это идиоматичный TypeScript.
- Когда тип очевиден из значения.

### Важный нюанс: Literal Types vs Widening

```typescript
// let — тип "расширяется" (widening)
let x = 5;              // тип: number (не 5!)
x = 10;                 // OK
x = "hello";            // Ошибка: string не присваивается number

// const — тип остаётся literal
const y = 5;            // тип: 5 (literal type, не number!)
y = 10;                 // Ошибка: нельзя переприсвоить const
```

**Почему это важно:**
- `const y = 5` → TypeScript запоминает, что `y` это именно `5`, а не просто `number`
- Это основа для **literal types**, которые ты будешь использовать в продвинутом TypeScript (Этап 1)
- В будущем это приведёт к **dependent types** в Lean 4, где значения могут быть частью типов

## 3. let vs const vs var

### var (избегай)

```typescript
var x = 5;
var x = 10;  // OK — можно переобъявить
console.log(x);  // 10

// Проблема 1: var имеет function scope, а не block scope
function test() {
  if (true) {
    var y = 5;
  }
  console.log(y);  // 5 — y видна снаружи if!
}

// Проблема 2: Hoisting
console.log(z);  // undefined (не ошибка!)
var z = 5;
// JavaScript "поднимает" объявление var в начало функции
```

**Почему var — зло:**
- Function scope приводит к непредсказуемому поведению
- Hoisting делает код трудным для понимания
- Можно случайно переобъявить переменную

### let (используй для изменяемых значений)

```typescript
let x = 5;
x = 10;  // OK
// x = "hello";  // Ошибка: string не присваивается number

// Block scope — предсказуемое поведение
function test() {
  if (true) {
    let y = 5;
  }
  // console.log(y);  // Ошибка: y не видна снаружи if
}

// Нельзя переобъявить в той же области видимости
let a = 5;
// let a = 10;  // Ошибка: Cannot redeclare block-scoped variable 'a'
```

**Когда использовать let:**
- Когда значение будет меняться (счётчики циклов, аккумуляторы)
- Когда ты не можешь использовать `const`

### const (используй по умолчанию)

```typescript
const PI = 3.14159;
// PI = 3;  // Ошибка: Cannot assign to 'PI' because it is a constant

// ВАЖНО: const означает "нельзя переприсвоить", а не "нельзя мутировать"
const person = { name: "Денис", age: 46 };
person.age = 47;  // OK — мы не переприсваиваем person, а мутируем объект
// person = { name: "Иван" };  // Ошибка: нельзя переприсвоить const

const numbers = [1, 2, 3];
numbers.push(4);  // OK — мутация массива
// numbers = [5, 6];  // Ошибка: нельзя переприсвоить const
```

**Почему const — это хорошо:**
- **Immutable by default**: если переменная не может меняться, код проще для понимания
- **Предотвращает ошибки**: нельзя случайно переприсвоить значение
- **Сигнализирует намерение**: `const` говорит "это значение не должно меняться"

### Правило для тебя

1. **По умолчанию используй `const`**
2. **Используй `let` только если значение действительно должно меняться**
3. **Никогда не используй `var`**

Это правило называется **"const by default"** и оно — основа современного JavaScript/TypeScript.

## 4. Операции с типами

### Арифметические операции (для number)

```typescript
let a = 10;
let b = 3;

console.log(a + b);   // 13 (сложение)
console.log(a - b);   // 7 (вычитание)
console.log(a * b);   // 30 (умножение)
console.log(a / b);   // 3.333... (деление)
console.log(a % b);   // 1 (остаток от деления, modulo)
console.log(a ** b);  // 1000 (возведение в степень)
```

### Особые случаи с числами

```typescript
// Деление на ноль
console.log(10 / 0);   // Infinity (не ошибка!)
console.log(-10 / 0);  // -Infinity
console.log(0 / 0);    // NaN (Not a Number)

// Проверка на NaN
let result = 0 / 0;
console.log(result === NaN);        // false! (NaN !== NaN)
console.log(Number.isNaN(result));  // true (правильный способ)

// Проверка на конечность
console.log(Number.isFinite(10));      // true
console.log(Number.isFinite(Infinity)); // false
console.log(Number.isFinite(NaN));     // false
```

**Почему это важно для твоего калькулятора:**
- Деление на ноль в JavaScript возвращает `Infinity`, а не бросает ошибку
- Ты должен **сам** проверить делитель на ноль и бросить ошибку
- `NaN` коварен: `NaN === NaN` возвращает `false`! Используй `Number.isNaN()`

### Строковые операции

```typescript
let firstName = "Денис";
let lastName = "Смирнов";

// Конкатенация
let fullName = firstName + " " + lastName;  // "Денис Смирнов"

// Template literals (предпочтительный способ)
let greeting = `Привет, ${firstName} ${lastName}!`;

// Методы строк
console.log(firstName.length);        // 6
console.log(firstName.toUpperCase()); // "ДЕНИС"
console.log(firstName.toLowerCase()); // "денис"
console.log(firstName.includes("ен")); // true
console.log(firstName.slice(0, 3));   // "Ден"
```

## 5. Приведение типов (Type Coercion)

JavaScript/TypeScript автоматически приводит типы в некоторых случаях. Это **опасно** и приводит к багам.

### Неявное приведение (избегай)

```typescript
// Строка + число = строка (конкатенация)
console.log("5" + 3);      // "53" (не 8!)
console.log("5" + 3 + 2);  // "532" (не 10!)

// Строка - число = число (вычитание)
console.log("5" - 3);      // 2 (строка приводится к числу)

// Булевые в числах
console.log(true + 1);     // 2 (true = 1, false = 0)
console.log(false + 1);    // 1

// Сравнение с приведением (==)
console.log(5 == "5");     // true (приведение типов!)
console.log(0 == false);   // true
console.log("" == false);  // true
```

### Строгое сравнение (всегда используй)

```typescript
// Строгое сравнение (===) — без приведения типов
console.log(5 === "5");    // false (разные типы)
console.log(0 === false);  // false
console.log("" === false); // false
```

**Правило для тебя:**
- **Всегда используй `===` и `!==`** вместо `==` и `!=`
- **Явно приводи типы**, если нужно: `Number("5")` или `parseInt("5", 10)`

## 6. Парсинг строк в числа

Для твоего калькулятора тебе нужно будет преобразовать строку от пользователя в число.

```typescript
// parseInt — для целых чисел
let int1 = parseInt("42", 10);      // 42 (всегда указывай основание 10!)
let int2 = parseInt("42.5", 10);    // 42 (отбрасывает дробную часть)
let int3 = parseInt("abc", 10);     // NaN

// parseFloat — для дробных чисел
let float1 = parseFloat("3.14");    // 3.14
let float2 = parseFloat("42");      // 42
let float3 = parseFloat("abc");     // NaN

// Number() — универсальный способ
let num1 = Number("42");            // 42
let num2 = Number("3.14");          // 3.14
let num3 = Number("abc");           // NaN
let num4 = Number("");              // 0 (осторожно!)
let num5 = Number("  42  ");        // 42 (игнорирует пробелы)
```

**Как проверить, что парсинг успешен:**

```typescript
let input = "abc";
let parsed = Number(input);

if (Number.isNaN(parsed)) {
  console.log("Ошибка: некорректное число");
} else {
  console.log("Успех:", parsed);
}
```

## 7. Типичные ошибки новичков

### Ошибка 1: Использование `var`

```typescript
// ❌ Плохо
var x = 5;

// ✅ Хорошо
const x = 5;  // или let, если нужно менять
```

### Ошибка 2: Сравнение через `==`

```typescript
// ❌ Плохо
if (x == 5) { ... }

// ✅ Хорошо
if (x === 5) { ... }
```

### Ошибка 3: Забыть проверить NaN

```typescript
// ❌ Плохо
let result = Number(input);
console.log(result);  // Может вывести NaN

// ✅ Хорошо
let result = Number(input);
if (Number.isNaN(result)) {
  throw new Error("Некорректное число");
}
```

### Ошибка 4: Мутация const

```typescript
// ❌ Непонимание
const numbers = [1, 2, 3];
numbers = [4, 5, 6];  // Ошибка!

// ✅ Понимание
const numbers = [1, 2, 3];
numbers.push(4);  // OK — мутация, а не переприсваивание
```

## 8. Связь с будущими темами курса

То, что ты учишь сейчас — это **простейшая форма системы типов**. Вот как это связано с будущим:

| Сейчас (Модуль 0.1) | Будущее |
|---------------------|---------|
| `let x: number = 5` | **Type-level программирование** (Этап 1) — типы как значения |
| `const x = 5` (literal type) | **Dependent types** (Этап 6) — значения как часть типов |
| `number`, `string` | **Алгебра типов** (Этап 6) — типы как алгебраические структуры |
| Type checking в TS | **Type inference** (Этап 6) — Algorithm W, Hindley-Milner |
| `===` vs `==` | **Soundness** (Этап 6) — гарантии системы типов |

Понимание того, как работают типы сейчас, даст тебе фундамент для понимания **Curry-Howard Isomorphism** (Этап 6): "программа = доказательство, тип = утверждение".
